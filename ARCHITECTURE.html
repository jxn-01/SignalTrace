Architecture / SignalTrace

One app.
One bounded agent.

SignalTrace is a Streamlit app that contains a tool-using LLM agent. The app handles inputs and display; the highlighted loop is where the model chooses and uses approved analysis tools.

Orange outline = agent runtime
What “agent” means here The model can choose its next approved tool and respond to that tool’s result. It cannot run arbitrary code, change KPI scope, write to business systems, or continue beyond four tool calls.

01 / App shell

The application owns the experience

Streamlit collects the request and data, validates the selected KPI scope, invokes the configured runtime, and presents the analyst-facing result. This layer is an app; by itself it is not the agent.

02 / Agent boundary

This is the agentic part

The Python runtime gives the model a task and an allowlist. The model chooses which tool to call next, receives its result, and can continue or return a structured brief. The runtime validates and executes each call.

Bounded agent runtime · agent.py · maximum four tool calls

Loop / stopTool result returns to the LLM for the next decision. Stop on a final structured response, an error/uncertainty handoff, or the four-call limit.
AllowlistNo arbitrary code, SQL, network tools, or write actions.
Scope lockTools cannot change the KPI, periods, or breakdown selected by the analyst.
Evidence firstQuality, comparison, or definition gaps force human review.
Human owns actionThe agent reports findings and checks; it never changes business systems.

The agent is required to call all three evidence tools before a normal final answer. Its discretion is in choosing their order, responding to returned evidence, and composing the result—not in changing the analyst’s scope.

03 / Runtime modes

Same app, different control flow

The configured model provider is Gemini or OpenAI. If neither key is active, SignalTrace can still demonstrate the calculations, but that fallback is not an agent run.

Live bounded agent

Streamlit sends the task context to the LLM. The model requests approved tools; Python validates and runs them; tool results return to the model until it finishes or reaches the bound.

Model-directed loop

Offline preview

Python runs data-quality, definition, and comparison functions in a fixed sequence. It labels the result as a preview and requires human review.

Fixed deterministic flow · not an agent
